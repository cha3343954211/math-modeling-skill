# Stage 1: 数据深度审计、符号系统与假设清单 (6~18h)

> **阶段定位**：奠定严谨扎实的研究地基。完成数据探索性分析（EDA）、清洗日志与证据链记录，全队统一全篇数学符号系统，输出《核心假设清单》与设问递进图，并跑通第一批 Baseline PoC 代码。

---

## 1. 阶段目标与准入/准出条件

- **输入依赖**：Stage 0 已选定的赛题文本与原始附件。
- **准出交付物**：
  1. `data/raw/`（只读原始数据）与 `data/processed/`（清洗后数据）
  2. `docs/references/`（**参考文献专属文件夹**：包含 `papers/` 论文PDF、`references.bib`、`literature_review.md`）
  3. `docs/data_processing_log.md`（数据清洗日志）
  4. `docs/symbols.md`（全局统一数学符号表）
  5. `docs/assumptions.md`（核心建模假设清单与合理性论证）
  6. `docs/problem_spec.md`（子问题递进关系图与问题规格说明书）
  7. `src/00_audit.py` & `src/01_baseline_poc.py`（小切片可行性代码）
- **人机审批点**：`[CP1 审批点]` 审批问题规格、符号定义、假设合理性与清洗规则。

## 2. 核心工作模块与执行标准

### 2.1 自动化问题初步分析与前沿文献归档 (Automated Problem Audit)
在执行 `/audit` 时，系统将自动运行 `scripts/auto_problem_audit.py`，全自动完成：
1. **要素结构化拆解**：自动解析题面，提取各问的输入已知量、求解目标、硬软约束与初选模型。
2. **设问递进图自动绘制**：绘制 Mermaid 设问递进图，明确 Q1（基准） $\to$ Q2（增量改装） $\to$ Q3（综合决策）的逻辑演进链。
3. **参考文献专属文件夹构建 (`docs/references/`)**：
   ```text
   docs/references/
   ├── papers/                  # 自动下载的 OA 权威论文 PDF 文件 (如 01_Smith_2021.pdf)
   ├── references.bib           # 自动生成的全量 LaTeX BibTeX 数据库 (直接可供论文引用)
   └── literature_review.md     # 自动合成的《文献综述与数模启发报告》(含方法对比与参数定界)
   ```
4. **真实参数基准定界**：从下载文献中自动提取真实物理/经济常数，为假设和 Stage 3 灵敏度分析提供证据支撑。

### 2.2 数据探索性分析 (EDA) 与证据链
- **只读存储**：原始数据存入 `data/raw/`，绝对禁止手工修改。
- **C题数据审计铁律（韩中庚教授评委准则）**：
  - **非大数据慎用填补套路**：空白/零值往往代表关键业务事实（如未销售/未进货），盲目均值/插值填补会篡改赛题本质；生理错漏数据优先通过机理反推，不可一删了之。
  - **成分数据单形空间校正**：对百分比成分数据（累加和理论为 $100\%$，如 2022-C），必须使用 `CompositionalDataTool` 进行均分误差归一化及**中心对称对数比变换 (CLR)**，消除闭合伪相关后再进行统计分析。
- **处理日志**：每项清洗必须记录到 `data_processing_log.md`（清洗规则、影响样本数、物理与统计合理性）。

### 2.3 全篇统一符号系统 (`symbols.md`)
必须在开始求解前制定全局统一的 LaTeX 符号表，防止团队三人写出互相冲突的符号：
```markdown
| 符号 | 物理/数学含义 | 单位 | 出现章节 |
|------|--------------|------|---------|
| $x_i(t)$ | 第 $i$ 类对象在 $t$ 时刻的状态值 | kg / 元 / 人 | 3.1, 3.2 |
| $\lambda$ | 增长率 / 感染率 / 转移强度 | $1/\text{day}$ | 3.1 |
| $C_{ij}$ | 从 $i$ 到 $j$ 的运输单位成本 | 万元/吨 | 4.1 |
```

### 2.4 核心假设清单与合理性论证 (`assumptions.md`)
评委审查重点：“假设是否合理，是否必要”。每条假设必须包含三要素：
1. **假设内容**：简明清晰的数学/现实陈述。
2. **合理性与必要性**：为何不能考虑全部细节？简化依据是什么？
3. **在模型中的位置与失效影响**：对应公式哪一项？如果假设不成立对结论有何冲击？

### 2.5 Baseline PoC 验证 (≤30行代码)
编程手必须在 12 小时内编写极简 Baseline 脚本，输出第一个可运行的基准结果，确保整条数据通路畅通无阻。
