# 数学建模论文写作指南

> 本文档是数学建模竞赛论文逐模块写作规范，覆盖标准结构、每模块写作要领、排版格式、题型侧重点和高分避坑清单。
> 配合 `detailed_paper_and_rigor_guide.md`（严谨性）和 `paper_quality_checklist.md`（质量门控）使用。

---

## 一、标准论文结构（12大模块）

数学建模竞赛论文推荐以下标准结构，按顺序排列：

| 序号 | 模块 | 必要性 | 简要说明 |
|------|------|--------|----------|
| 1 | 标题 | 必须 | 简洁精准，概括问题和方法 |
| 2 | 摘要 | 必须（最重要） | 全文精华，300-500字 |
| 3 | 关键词 | 必须 | 3-5个，反映核心方法和领域 |
| 4 | 问题重述 | 必须 | 用自己的话复述题意，不照抄 |
| 5 | 问题分析 | 必须 | 分析题型、难点、方法选择理由 |
| 6 | 模型假设 | 必须 | 逐条编号，服务于建模 |
| 7 | 符号说明 | 必须 | 表格形式，定义所有符号 |
| 8 | 模型建立与求解 | 核心 | 公式推导+求解过程+结果 |
| 9 | 检验与灵敏度分析 | 必须 | 验证模型可靠性和稳健性 |
| 10 | 模型评价 | 必须 | 优点+缺点，客观全面 |
| 11 | 参考文献 | 必须 | 3-8篇，格式统一 |
| 12 | 附录 | 推荐 | 核心代码、支撑材料说明 |

> **注**：部分竞赛还要求"承诺书""目录"等，按具体赛事要求补充。

## 二、逐模块详细写作规范

### 2.1 标题

**要求**：
- 简洁精准，控制在20字以内
- 居中，黑体，小二号（18pt）
- 应包含核心方法或问题关键词

**写法示例**：
```
✅ 基于多目标优化的城市共享单车动态调度模型
✅ 基于熵权-TOPSIS的水质综合评价模型
❌ 一个关于水质问题的数学模型（太笼统）
❌ 基于深度学习、随机森林、XGBoost和集成方法的多模型融合预测研究（太长）
```

---

### 2.2 摘要（重中之重）

摘要是评委阅读的第一部分，直接决定第一印象。**摘要质量 ≈ 论文质量的50%**。

#### 2.2.1 四段逻辑结构

| 段落 | 内容 | 字数参考 |
|------|------|----------|
| 第一段 | **背景+任务**：问题背景（1-2句）+ 本文要解决什么（每个子问题一句话） | 50-80字 |
| 第二段 | **方法**：每个子问题用了什么方法（方法名+一句话原理） | 80-120字 |
| 第三段 | **过程+结果**：关键求解过程 + 每个子问题的核心数值结果（必须有数字！） | 100-150字 |
| 第四段 | **评价+结论**：模型检验结果 + 优缺点 + 最终结论/建议 | 50-80字 |

#### 2.2.2 摘要三要素（缺一不可）

1. **方法要素**：明确写出每个子问题使用的模型/算法名称
   - ✅ "针对问题一，建立基于熵权法的综合评价模型"
   - ❌ "针对问题一，建立了一个评价模型"（缺方法名）

2. **数据要素**：关键数值结果必须写出
   - ✅ "最优方案A的综合得分为0.873，较基线提升12.4%"
   - ❌ "最优方案表现较好"（无数据）

3. **结论要素**：最终回答题目要求
   - ✅ "推荐方案A作为最终调度策略，预计可降低运营成本18%"
   - ❌ "本文建立了模型并求解"（无结论）

#### 2.2.3 摘要常见错误

| 错误 | 后果 |
|------|------|
| 摘要没有数字 | 直接降档，评委无法判断结果质量 |
| 摘要超过1页 | 格式不合格，必须压缩到1页内 |
| 摘要写成问题重述 | 浪费篇幅，没告诉评委你做了什么 |
| 子问题描述不对齐 | 摘要写了3个问题但论文只有2个，或反过来 |
| 方法名字不准确 | 评委无法判断你的方法是否合适 |

#### 2.2.4 摘要模板

```markdown
## 摘要

[背景句] 近年来，XX问题日益受到关注。[任务句] 本文针对XX问题的N个子问题，
分别建立XX模型、XX模型和XX模型进行求解。

针对问题一，提出基于XX的XX模型。首先，对XX数据进行预处理，
然后利用XX方法XX，最终得到XX结果为XX。

针对问题二，建立基于XX的XX优化模型。以XX为目标函数，XX为约束条件，
采用XX算法求解，得到最优方案为XX，较基线提升XX%。

针对问题三，构建基于XX的预测模型。将数据划分为训练集和测试集，
模型在测试集上MAE为XX，RMSE为XX，表现出良好的预测精度。

经灵敏度分析，模型对XX参数变化在±10%范围内结果稳定（波动<5%）。
本文模型具有XX优点，但也存在XX局限，未来可从XX方面改进。

关键词：关键词1；关键词2；关键词3；关键词4；关键词5
```

### 2.3 关键词

**要求**：
- 3-5个，用分号或逗号分隔
- 反映核心方法、问题领域、核心技术
- 排列顺序：问题领域在前，方法在后

**示例**：
```
关键词：水质评价；熵权法；TOPSIS；综合评价模型
关键词：共享单车；动态调度；多目标优化；遗传算法
关键词：时间序列预测；ARIMA；灰色预测；组合预测
```

### 2.4 问题重述

**要求**：
- **用自己的话复述**，绝不照抄题干原文
- 补充背景信息（1-2句），说明问题的实际意义
- 将题目要求分解为明确的子任务
- 字数300-500字

**写法结构**：
```
1. 背景引入（1-2句）：说明问题的实际应用场景
2. 问题概述（2-3句）：概括题目要解决什么
3. 子问题分解：逐个列出每个子问题的要求
   - 问题一：要求……
   - 问题二：在问题一的基础上，进一步要求……
   - 问题三：……
```

**注意事项**：
- ✅ "本文需解决某城市共享单车调度优化问题"（用自己的话）
- ❌ 直接复制题目原文（抄袭嫌疑）
- 子问题之间的依赖关系要交代清楚

---

### 2.5 问题分析

**要求**：
- 对每个子问题进行独立分析
- 分析题型（预测/优化/评价/分类/仿真等）
- 指出难点和关键挑战
- 说明方法选择的理由
- 字数600-1000字

**写法结构**：
```
对于问题一：
- 题型识别：本题属于XX类问题
- 难点分析：主要难点在于XX（如数据缺失、多目标冲突等）
- 方法选择：考虑到XX特点，选择XX方法，原因是XX
- 与其他方法对比：XX方法相比YY方法在本题场景下更合适，因为XX

对于问题二：
（同上结构）
```

**题型-方法快速映射**：

| 题型 | 典型方法 |
|------|----------|
| 评价 | 熵权-TOPSIS、AHP、组合赋权、灰色关联 |
| 预测 | ARIMA、灰色预测、随机森林、XGBoost、组合预测 |
| 优化 | 线性/整数规划、动态规划、遗传算法、模拟退火 |
| 分类 | SVM、随机森林、XGBoost、KNN |
| 聚类 | KMeans、DBSCAN、层次聚类 |
| 仿真 | 蒙特卡洛、元胞自动机、Agent-based |
| 图论 | 最短路径、最小生成树、网络流 |

### 2.6 模型假设

**要求**：
- 逐条编号，每条假设独立成段
- 服务于建模（假设必须在后续模型中被实际使用）
- 合理且必要，不写废话假设
- 每条假设简要说明理由
- 通常5-10条

**写法模板**：
```
假设1：假设研究区域内的共享单车需求在一天内呈周期性变化。
理由：实际数据显示工作日和周末的骑行模式有明显规律，该假设便于建立需求预测模型。

假设2：忽略车辆调度过程中的交通拥堵影响。
理由：调度车辆在非高峰时段运行，交通影响较小，简化后不影响核心结论。

假设3：每辆单车的折旧成本与其使用次数成正比。
理由：符合实际情况，且便于在目标函数中量化成本。
```

**常见错误**：
- ❌ "假设数据是正确的"（废话假设）
- ❌ "假设问题很简单"（无意义）
- ✅ 每条假设都能在模型公式中找到对应

---

### 2.7 符号说明

**要求**：
- 表格形式，三线表
- 覆盖公式中出现的所有符号
- 包含符号、含义、单位三列
- 按类别分组（变量、参数、集合等）

**格式模板**：

| 符号 | 含义 | 单位 |
|------|------|------|
| $x_i$ | 第 $i$ 个备选方案 | — |
| $w_j$ | 第 $j$ 个评价指标的权重 | — |
| $d_{ij}$ | 方案 $i$ 在指标 $j$ 上的标准化值 | — |
| $C$ | 日均运营总成本 | 元/天 |
| $N$ | 研究区域内的单车总数 | 辆 |
| $T$ | 调度时间窗 | 小时 |

**注意**：
- 希腊字母（$\alpha, \beta, \gamma$ 等）和特殊符号要说明
- 上标/下标的含义要交代
- 单位统一用国际单位制

### 2.8 模型建立与求解

这是论文的核心部分，占全文篇幅的50%-60%。

#### 2.8.1 整体结构

每个子问题按以下顺序展开：

```
4.X 问题X的模型建立与求解
  4.X.1 问题分析与思路
  4.X.2 数据预处理
  4.X.3 模型建立（公式推导）
  4.X.4 模型求解（算法/求解过程）
  4.X.5 结果与分析（表格+图表+解读）
```

#### 2.8.2 公式推导规范

- **公式必须有来源**：不能突然出现一个公式，要说明推导过程
- **目标函数要解释现实含义**：不只是写数学公式，要说清楚它代表什么
- **约束条件要标注来源**：来自题目哪句话，或来自什么现实限制
- **公式编号**：按章编号，如 (3.1), (3.2)，或全文连续编号 (1), (2)...

**示例写法**：
```
以日均运营总成本最小为目标，建立如下优化模型：

min  C = C_调度 + C_折旧 + C_惩罚    (3.1)

其中，调度成本 C_调度 表示调度车辆的燃油和人工费用：
C_调度 = ∑_{i=1}^{n} c_d · d_i · z_i    (3.2)

式中，$c_d$ 为单位距离调度成本（元/km），$d_i$ 为第 $i$ 条调度路径的距离，
$z_i$ 为0-1决策变量，$z_i=1$ 表示启用该路径。

约束条件：
（1）流量守恒约束：每个站点的流入量等于流出量，来自题目中"调度前后站点车辆数平衡"的要求；
（2）容量约束：每辆车载重不超过容量上限 $Q$；
（3）时间窗约束：调度必须在运营开始前完成。
```

#### 2.8.3 图表规范

| 要素 | 规范 |
|------|------|
| 图题 | 在图下方，格式"图X：描述" |
| 表题 | 在表上方，格式"表X：描述" |
| 编号 | 按章编号（图3.1）或全文连续编号（图1） |
| 单位 | 坐标轴、图例必须标注单位 |
| 正文引用 | 每张图表必须在正文中引用并解释 |
| 解读 | 每张图/表后至少2-4句分析文字 |

**图表解读写作模板**：
```
由图3.1可以看出，[趋势/特征描述]。
具体而言，[数值对比]，[原因解释]。
这说明[实际意义]，[对建模的影响]。
```

#### 2.8.4 求解过程写法

- 给出算法步骤或伪代码（不需要完整代码，但要展示思路）
- 说明求解工具（Python/MATLAB + 具体库名）
- 给出关键参数设置（如遗传算法的种群大小、迭代次数）
- 固定随机种子，确保可复现

### 2.9 检验与灵敏度分析

**要求**：
- 每个模型都必须有检验环节
- 灵敏度分析至少涉及2个关键参数
- 用数据/图表说明模型的稳健性

#### 2.9.1 检验方法

| 模型类型 | 检验方法 |
|----------|----------|
| 预测类 | MAE、RMSE、MAPE、R²、残差分析、训练测试划分 |
| 优化类 | 约束满足检查、目标函数对比、可行性验证 |
| 评价类 | 排名稳定性、权重合理性、等权对比 |
| 分类类 | 混淆矩阵、F1-score、交叉验证 |
| 聚类类 | 轮廓系数、簇稳定性 |

#### 2.9.2 灵敏度分析写法

```
为检验模型对关键参数的敏感性，分别对XX参数和YY参数进行±10%~±20%的扰动实验。

由表X可知，当XX参数变化±20%时，目标函数值变化幅度为X.X%，
说明模型对该参数不敏感，具有较好的稳健性。
而YY参数变化±10%时，目标函数值变化达到X.X%，
表明模型对YY参数较为敏感，在实际应用中应重点关注该参数的准确取值。
```

### 2.10 模型评价

**要求**：
- 客观全面，既要写优点也要写缺点
- 每条评价要有具体分析，不写套话
- 优点数量 ≥ 缺点数量
- 可附带改进建议
- 字数800-1200字

#### 2.10.1 优点写作

每条优点展开为"原理+效果+价值"三段式：

```
优点1：本文采用熵权法客观确定指标权重，避免了主观赋权的人为偏差。
实验表明，与等权方法相比，熵权法的评价结果与专家评分的相关系数从0.72提升至0.91。
该方法在数据驱动的评价场景中具有广泛的适用性。

优点2：（同上结构）
```

#### 2.10.2 缺点写作

每条缺点展开为"局限+影响+改进方向"三段式：

```
缺点1：本文假设调度成本与距离成线性关系，未考虑交通拥堵等非线性因素。
在高峰时段，实际调度成本可能显著高于模型预测值。
改进方向：引入时变交通模型，将调度成本建模为时间的函数。

缺点2：（同上结构）
```

### 2.11 参考文献

**要求**：
- 数量：3-8篇（推荐5-6篇）
- 格式统一，优先使用GB/T 7714格式
- 涵盖：经典教材、相关论文、数据来源、工具文档
- 不要引用过时文献（10年以上慎用）

**GB/T 7714格式示例**：

```
[1] 司守奎, 孙兆亮. 数学建模算法与应用[M]. 北京: 国防工业出版社, 2015.
[2] 张三, 李四. 基于熵权-TOPSIS的城市水质评价方法[J]. 环境科学, 2020, 41(3): 123-130.
[3] 王五. 共享单车调度优化研究[D]. 北京: 北京交通大学, 2019.
[4] 国家统计局. 中国统计年鉴-2023[DB/OL]. https://data.stats.gov.cn, 2023.
```

### 2.12 附录

**要求**：
- 核心代码（关键函数，非全部代码）
- 数据来源说明
- 复现步骤（运行环境、依赖库、运行命令）
- 冻结数字文件（L3竞赛必做）
- 支撑材料目录结构

**附录内容模板**：
```
附录A 核心代码
A.1 数据预处理代码（Python）
A.2 模型求解代码（Python/MATLAB）

附录B 数据来源与说明
B.1 数据表字段说明
B.2 数据预处理审计表

附录C 复现说明
C.1 运行环境：Python 3.11, numpy 1.24, pandas 2.0, ...
C.2 运行步骤：1. 下载数据 → 2. 运行 preprocessing.py → 3. 运行 solve.py
C.3 输出文件说明
```

## 三、不同题型写作侧重点

| 题型 | 摘要侧重点 | 模型建立侧重点 | 检验侧重点 | 结果呈现 |
|------|------------|----------------|------------|----------|
| **评价类** | 权重方法+排名结果+分数 | 权重计算过程+综合评价函数 | 排名稳定性+权重合理性 | 排名表+雷达图 |
| **预测类** | 预测方法+精度指标+预测值 | 模型选择理由+训练测试划分 | MAE/RMSE/MAPE+残差图 | 拟合效果图+预测曲线 |
| **优化类** | 优化目标+约束+最优解 | 目标函数推导+约束来源 | 约束满足+参数敏感性 | 最优方案表+甘特图 |
| **分类类** | 分类方法+各类别含义+精度 | 特征选择+分类器设计 | 混淆矩阵+F1+交叉验证 | 混淆矩阵图+特征重要性 |
| **聚类类** | 聚类数+各类别特征+轮廓系数 | 距离度量+聚类算法 | 轮廓系数+簇稳定性 | 聚类散点图+类特征表 |
| **仿真类** | 仿真方法+关键参数+仿真结果 | 仿真模型构建+参数设定 | 多次运行稳定性 | 时间序列图+统计分布 |
| **图论类** | 图模型+最优路径/结构 | 图的构建+算法选择 | 最优性验证+复杂度分析 | 网络图+路径标注 |
| **机理类** | 物理/化学原理+模型参数+拟合度 | 机理方程推导+参数拟合 | 拟合优度+参数合理性 | 机理图+拟合曲线 |

### 4.2 字体与字号规范

| 元素 | 字体 | 字号 | 对齐 |
|------|------|------|------|
| 论文标题 | 黑体 | 小二（18pt） | 居中 |
| 一级标题 | 黑体 | 三号（16pt） | 居中或左对齐 |
| 二级标题 | 黑体 | 四号（14pt） | 左对齐 |

| 参考文献 | 宋体 | 五号（10.5pt） | 悬挂缩进 |

### 4.3 页边距与行距

- 页边距：上下左右均2.5cm
- 行距：1.25-1.5倍（推荐1.35倍）
- 段前段后：0.5行
- 首行缩进：2字符

### 4.4 公式规范

- 公式居中，编号右对齐
- 公式中所有符号必须在符号说明中定义
- 长公式使用 `aligned`/`split`/`multline` 拆行
- 公式不得被裁切、越过页边距或与编号重叠

### 4.5 图表规范

- 表格优先使用三线表（`booktabs`）
- 宽表使用 `longtable` 或 `resizebox`
- 图题在图下方，表题在表上方
- 每张图表必须有编号、单位、正文引用和解读

### 4.6 页码与页眉

- 页码底部居中
- 页眉写论文题名缩写（或留空）
- 目录和摘要页使用罗马数字（可选），正文使用阿拉伯数字

## 五、高分避坑总结（6大高频扣分点）

### 坑1：摘要无数字

**现象**：摘要只写"本文建立了XX模型，得到了较好的结果"
**后果**：评委无法判断结果质量，直接降档
**正确做法**：摘要必须包含每个子问题的关键数值结果
```
✅ "模型在测试集上MAE为0.032，RMSE为0.045，R²达0.967"
❌ "模型取得了较好的预测效果"
```

### 坑2：先写结果后补模型

**现象**：先跑出结果，再倒推模型解释
**后果**：论文逻辑倒置，评委能看出来
**正确做法**：按"问题→假设→模型→求解→结果"的正向逻辑写作

### 坑3：图表无解读

**现象**：放了一张图或表，但正文没有任何分析
**后果**：评委认为作者不理解自己的结果
**正确做法**：每张图/表后至少2-4句解读
```
由图3.1可以看出，方案A的综合得分显著高于其他方案。
具体而言，方案A得分0.873，较方案B（0.741）高出17.8%。
这主要得益于方案A在效率指标上的优势（权重最高）。
同时，方案C虽然成本最低，但稳定性偏低导致总分下降。
```

### 坑4：数字不一致

**现象**：摘要写0.873，正文写0.871，表格里又是0.875
**后果**：评委严重质疑论文可信度
**正确做法**：所有数字从 `frozen_numbers.json` 或最终结果表读取，人工核对

### 坑5：没有Baseline对比就宣称更优

**现象**：主模型结果直接展示，没有与简单方法对比
**后果**：无法证明模型的价值
**正确做法**：必须有Baseline，必须说明为什么主模型更好
```
| 方法 | MAE | RMSE | R² |
|------|-----|------|----|
| 均值预测（Baseline） | 0.089 | 0.112 | 0.724 |
| 线性回归（Baseline） | 0.067 | 0.085 | 0.831 |
| XGBoost（本文） | 0.032 | 0.045 | 0.967 |
```

### 坑6：模型评价写套话

**现象**：优点写"模型效果好"，缺点写"数据不够多"
**后果**：评委认为作者没有深入思考
**正确做法**：每条评价展开为"原理+效果+价值"或"局限+影响+改进"
```
✅ "本文采用熵权法客观确定指标权重，避免了主观赋权的人为偏差。
   实验表明，与等权方法相比，熵权法的评价结果与专家评分的相关系数从0.72提升至0.91。"
❌ "模型优点是效果好，缺点是有些不足。"
```

## 六、写作流程建议（竞赛时间分配）

| 阶段 | 时间占比 | 任务 |
|------|----------|------|
| 审题与分析 | 10% | 题目解析、方法选择、假设制定 |
| 建模与求解 | 40% | 编程求解、结果验证、数据冻结 |
| 论文写作 | 40% | 摘要、正文、图表、参考文献 |
| 检查与修改 | 10% | 数字核对、格式统一、PDF检查 |

**论文写作顺序建议**（非摘要先行）：
1. 先写问题分析、模型假设、符号说明（框架）
2. 再写模型建立与求解（核心内容）
3. 然后写检验与模型评价
4. 最后写摘要和标题（全文浓缩）
5. 附录和参考文献最后补充
