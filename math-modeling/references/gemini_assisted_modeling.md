# Gemini辅助建模流程

> 使用Google Gemini辅助数学建模的完整工作流

---

## 一、何时使用Gemini

### 适合使用Gemini的场景
1. **文献调研**：快速了解某个方法的背景、原理、应用场景
2. **代码审查**：检查代码逻辑、查找bug、优化性能
3. **翻译润色**：中英文互译、学术语言润色
4. **方法对比**：比较不同方法的优缺点
5. **思路启发**：遇到瓶颈时寻求新的解决思路
6. **公式推导**：检查数学推导过程
7. **论文结构**：优化论文组织和表达

### 不适合使用Gemini的场景
1. **最终结果**：Gemini的输出需要人工验证，不能直接作为最终结果
2. **精确计算**：Gemini可能产生计算错误
3. **专业领域**：某些专业领域可能有错误或过时信息
4. **原创性要求**：核心创新点应由团队独立完成

## 二、如何调用Gemini

### 启动流程
```
1. 打开Chrome浏览器
2. 使用专用 Gemini 登录 Profile（已登录账号）
3. 访问 https://gemini.google.com
4. 确认已登录账号
5. 开始对话
```

### Prompt技巧

#### 基础Prompt结构
```
[角色设定] + [任务描述] + [约束条件] + [输出格式]
```

#### 示例：文献调研
```
你是一位数学建模专家。请帮我调研"多目标优化中的帕累托前沿求解方法"。
要求：
1. 列出3-5种主流方法
2. 每种方法说明原理、优缺点
3. 推荐最适合CUMCM竞赛使用的方法
4. 用中文回答，条理清晰
```

#### 示例：代码审查
```
请审查以下Python代码，检查：
1. 逻辑错误
2. 性能问题
3. 可读性改进
4. 边界条件处理

[粘贴代码]
```

#### 示例：翻译润色
```
请将以下中文翻译为学术英语，要求：
1. 用词准确、专业
2. 句式符合学术论文规范
3. 保持原意不变

[粘贴中文文本]
```

### Prompt优化技巧
1. **明确角色**：告诉Gemini你希望它扮演什么角色
2. **分步提问**：复杂任务拆分为多个简单问题
3. **提供上下文**：给出背景信息和约束条件
4. **指定格式**：要求特定的输出格式（表格、列表、代码）
5. **追问细化**：对不满意的回答进行追问

## 三、Gemini模型选择策略

### 模型版本
| 模型 | 特点 | 推荐场景 |
|------|------|---------|
| Gemini 2.5 Pro | 最强推理能力 | 复杂问题分析、数学推导 |
| Gemini 2.5 Flash | 快速响应 | 简单任务、快速查询 |
| Gemini 2.0 Flash | 平衡速度与能力 | 日常使用、代码生成 |

### 选择建议
- **文献调研**：Gemini 2.5 Pro（需要深度理解）
- **代码生成**：Gemini 2.5 Flash（快速生成）
- **翻译润色**：Gemini 2.5 Flash（快速且质量可接受）
- **数学推导**：Gemini 2.5 Pro（需要精确推理）
- **思路启发**：任意模型（主要是获取灵感）

## 四、Gemini输出评估清单（必须人工验证）

### 验证维度
1. **事实准确性**
   - [ ] 检查引用的文献是否真实存在
   - [ ] 验证数学公式是否正确
   - [ ] 确认数据和统计信息是否准确

2. **逻辑一致性**
   - [ ] 推理过程是否合理
   - [ ] 结论是否与前提一致
   - [ ] 是否有自相矛盾之处

3. **适用性评估**
   - [ ] 方法是否适合当前问题
   - [ ] 是否考虑了问题的特殊性
   - [ ] 是否有更优的替代方案

4. **原创性检查**
   - [ ] 是否直接抄袭现有内容
   - [ ] 创新点是否足够
   - [ ] 是否符合学术规范

5. **代码验证**
   - [ ] 代码能否运行
   - [ ] 结果是否正确
   - [ ] 是否有隐藏的bug

### 验证方法
- **交叉验证**：用不同方法验证Gemini的结果
- **文献核实**：检查Gemini引用的文献
- **代码测试**：运行Gemini生成的代码
- **专家审核**：请老师或同学帮忙检查

## 五、Gemini辅助建模工作流

### 完整工作流
```
阶段1：问题理解
├── 用Gemini分析题目要求
├── 提取关键信息
└── 生成问题框架

阶段2：文献调研
├── 用Gemini搜索相关方法
├── 比较不同方法
└── 确定技术路线

阶段3：模型构建
├── 用Gemini检查公式推导
├── 生成代码框架
└── 验证模型逻辑

阶段4：结果分析
├── 用Gemini分析结果含义
├── 生成可视化代码
└── 检查结果合理性

阶段5：论文写作
├── 用Gemini润色文字
├── 翻译英文摘要
└── 检查论文结构
```

### 工作流示例：以"传染病模型"为例
```
1. 用Gemini分析SIR/SEIR模型原理（5min）
2. 用Gemini比较不同传染病模型（10min）
3. 用Gemini检查微分方程推导（15min）
4. 用Gemini生成Python求解代码（20min）
5. 用Gemini分析灵敏度分析结果（10min）
6. 用Gemini润色论文相关章节（15min）
```

### 时间分配建议
- Gemini辅助时间：总时间的10-15%
- 人工验证时间：Gemini使用时间的2-3倍
- 总原则：Gemini是助手，不是替代

## 六、典型使用场景示例

### 场景1：快速了解陌生领域
```
用户：我需要解决一个关于"车辆路径规划"的问题，
但我对这个领域不熟悉。请用中文介绍：
1. 这个问题的基本概念
2. 常用的建模方法
3. 经典的求解算法
4. CUMCM竞赛中常见的变体

要求：条理清晰，适合初学者理解。
```

### 场景2：代码调试
```
用户：以下Python代码运行出错，请帮我检查：

import numpy as np
def optimize(x):
    return x**2 - 4*x + 4

result = optimize([1, 2, 3])
print(result)

错误信息：TypeError: unsupported operand type(s) for **: 'list' and 'int'

请解释错误原因并修复。
```

### 场景3：方法对比
```
用户：在解决"多目标优化"问题时，有以下几种方法：
1. 加权求和法
2. ε-约束法
3. 遗传算法（NSGA-II）
4. 粒子群优化

请从以下维度对比：
- 实现复杂度
- 求解质量
- 计算效率
- 适用场景
- CUMCM竞赛中的使用频率

用表格形式呈现。
```

### 场景4：论文润色
```
用户：请帮我润色以下学术段落，要求：
1. 用词更专业
2. 句式更流畅
3. 逻辑更清晰
4. 保持原意

原文：我们用了一个方法来解决问题，这个方法效果还不错，
比其他方法好一些，具体好多少我们算了一下，大概是10%左右。
```

### 场景5：公式推导检查
```
用户：请检查以下数学推导是否正确：

假设：dN/dt = rN(1 - N/K)

其中N是种群数量，r是增长率，K是环境容纳量。

求解：
1. 分离变量：dN/(N(1-N/K)) = rdt
2. 部分分式分解：1/(N(1-N/K)) = 1/N + 1/(K-N)
3. 积分：ln|N| - ln|K-N| = rt + C
4. 整理：N = K/(1 + Ce^(-rt))

请验证每一步是否正确。
```

## 七、注意事项

### 使用原则
1. **辅助为主**：Gemini是工具，不是替代
2. **验证必须**：所有输出必须人工验证
3. **创新独立**：核心创新点应由团队完成
4. **学术诚信**：不能直接使用Gemini生成的内容不注明来源

### 常见误区
- ❌ 完全依赖Gemini，不验证输出
- ❌ 直接复制Gemini的代码不测试
- ❌ 用Gemini替代团队思考
- ❌ 忽略Gemini的局限性

### 最佳实践
- ✅ 将Gemini作为"第二个大脑"使用
- ✅ 用Gemini加速调研和代码生成
- ✅ 用Gemini进行交叉验证
- ✅ 用Gemini润色和翻译
- ✅ 保持团队独立思考和创新
