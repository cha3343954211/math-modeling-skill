# 数学建模人机协同与分阶段审批协议 (Human-in-the-Loop Protocol)

> 本协议用于规范 AI 助手与参赛团队/专家之间的高效分工与闭环协同。将数学建模全过程拆解为 5 个核心检查点（Checkpoints），在关键决策节点由人类把关、审批、修正或提出定向意见，杜绝 AI “黑盒盲跑”。

---

## 1. 人机分工原则 (Division of Responsibilities)

| 维度 | AI 助手的核心职责 (Executor & Advisor) | 人类专家/队员的核心职责 (Decision Maker & Judge) |
|------|--------------------------------------|---------------------------------------------|
| **审题与理解** | 快速提取题干事实、生成问题规格草案、构建设问递进图与数据审计摘要 | 确认赛题意图是否准确、判断题目深层物理/业务背景、审核假设是否合理 |
| **方案选型** | 提供 Baseline + 多个主模型候选（含优缺点/复杂度/适用条件对比），运行小规模 PoC | 决策主攻技术路线（如选择经典机理模型还是数据驱动模型）、否决不切实际的候选 |
| **建模求解** | 严格数学公式推导、编写高质量复现代码、执行数值求解与约束检查 | 核查公式逻辑与物理量纲、评估参数设置、对异常结果提出物理/现实质疑 |
| **验证与诊断** | 自动执行对照实验、时间外验证、DW自相关检验、灵敏度弹性分析 | 审查关键指标与图表趋势、判断结果是否反常识、指定需要重点深入的分析方向 |
| **论文撰写** | 按规范生成 LaTeX 论文初稿、绘制规范图表、生成三段式摘要与大纲 | 审定论文行文逻辑、提炼核心创新点与故事叙事、把控论文排版与最终质量 |

## 2. 五大核心审批检查点 (The 5 Approval Checkpoints)

```
[赛题发布/输入]
       │
       ▼
┌────────────────────────────────────────┐
│  Checkpoint 1: 题意理解与假设清单审批   │ ◄── 人类：确认题意、修正假设、增补背景
└──────────────────┬─────────────────────┘
                   │ [Approve]
                   ▼
┌────────────────────────────────────────┐
│  Checkpoint 2: 建模方案与候选路线评审   │ ◄── 人类：选择主模型、决定创新切口、否决劣解
└──────────────────┬─────────────────────┘
                   │ [Approve]
                   ▼
┌────────────────────────────────────────┐
│  Checkpoint 3: 模型推导与中间求解复核   │ ◄── 人类：检查推导、评估量纲、调整超参数
└──────────────────┬─────────────────────┘
                   │ [Approve]
                   ▼
┌────────────────────────────────────────┐
│  Checkpoint 4: 对照验证与灵敏度审批     │ ◄── 人类：确认数字可信、检查误差/反常识
└──────────────────┬─────────────────────┘
                   │ [Approve]
                   ▼
┌────────────────────────────────────────┐
│  Checkpoint 5: 论文大纲、摘要与终审交付 │ ◄── 人类：精修摘要、把关叙事、终审确认提交
└────────────────────────────────────────┘
```

---

### Checkpoint 1: 题意理解与假设清单审批 (CP1: Problem Spec & Assumptions)

- **AI 交付物**：
  1. `problem_spec.md`：输入输出、目标函数、硬软约束、已知事实；
  2. `assumptions.md`：核心假设清单（含必要性、合理性、模型映射与失效影响）；
  3. `data_audit_summary.md`：数据缺失率、异常值、维度分布与特征说明。
- **人类审查要点**：
  - [ ] 题目核心目标是否理解偏差？（例如把多目标误当单目标）
  - [ ] 核心假设是否符合实际？是否有“为简化而严重失真”的假设？
  - [ ] 数据清洗规则是否合理？有无不当剔除关键样本？
- **人机交互指令**：
  - `/approve`：确认题意与假设，进入方案选择。
  - `/revise assumption [内容]`：修改或删除某条假设。
  - `/add assumption [内容]`：补充新的现实/背景约束。

---

### Checkpoint 2: 建模方案与候选路线评审 (CP2: Model Selection & Architecture)

- **AI 交付物**：
  1. `model_proposal.md`：每个子问题提供至少 2 套候选方案（Baseline + 主模型），附优缺点、计算复杂度与数据适配性说明；
  2. `poc_results.md`：候选模型的最小可行性验证（PoC，≤30行代码小切片运行结果）。
- **人类审查要点**：
  - [ ] Baseline 是否足够简单且具可解释性？
  - [ ] 主模型是否切合题意？是否过度拟合或盲目堆叠深度学习？
  - [ ] 方案是否符合多问之间的递进继承逻辑（Q1→Q2→Q3）？
- **人机交互指令**：
  - `/approve`：采纳 AI 推荐的默认最佳方案组合。
  - `/select [Q1=A, Q2=B]`：指定人类偏好的模型路线。
  - `/reject [理由]`：否决当前方案，要求更换模型理论（如改用机理微分方程而非黑盒回归）。

---

### Checkpoint 3: 核心模型推导与中间求解复核 (CP3: Formulation & Solvers)

- **AI 交付物**：
  1. `model_formulation.md`：数学公式完整推导、变量符号表、状态方程/目标函数/约束体系；
  2. `intermediate_results.md`：代码运行的中间解、求解器状态（Optimal/Infeasible）、约束满足率。
- **人类审查要点**：
  - [ ] 数学公式与物理量纲是否自洽？
  - [ ] 优化模型是否有未考虑的隐式约束（如非负性、整数性、容量上限）？
  - [ ] 求解结果是否出现反常数值（如负价格、超光速、效率>100%）？
- **人机交互指令**：
  - `/approve`：公式与中间解无误，继续深入验证。
  - `/tune [参数名=新数值]`：调整特定参数/权重或初始边界条件。
  - `/add constraint [约束条件]`：追加遗漏的模型约束。

---

### Checkpoint 4: 对照验证与灵敏度分析审批 (CP4: Validation & Sensitivity)

- **AI 交付物**：
  1. `validation_report.md`：Baseline 对照表、改装效果表、时间外/滚动误差或交叉验证得分；
  2. `sensitivity_analysis.md`：关键参数弹性 $S = \frac{x}{y}\frac{dy}{dx}$、扰动（±10%~±20%）稳健性曲线；
  3. `frozen_numbers.json`：所有子问题的最终核心数值结果草案。
- **人类审查要点**：
  - [ ] 改进模型相比 Baseline 是否有真实、同口径的指标提升？
  - [ ] 灵敏度分析参数是否具有现实决策意义？
  - [ ] 关键数字是否稳定可信？是否可以正式冻结供论文引用？
- **人机交互指令**：
  - `/approve`：正式冻结数字 (`freeze numbers`)，进入论文撰写。
  - `/test_sensitivity [参数列表]`：指定需要重点补充灵敏度分析的参数。
  - `/recalibrate [模型/数据]`：针对异常指标重新拟合或调优。

---

### Checkpoint 5: 论文大纲、摘要与终审交付 (CP5: Paper & Delivery Review)

- **AI 交付物**：
  1. `paper_outline.md`：一级与二级标题大纲、篇幅规划、图表插入点；
  2. `abstract_draft.md`：严格 1 页的三段式摘要（研究背景+分问方法与关键数字+稳健性结论）；
  3. 编译好的完整 PDF 论文与支撑材料包。
- **人类审查要点**：
  - [ ] 摘要是否包含各问的具体方法名称与核心定量结果？
  - [ ] 正文篇幅是否满足 18~25 页硬规范（第一页摘要、第二页目录、正文从1标页码）？
  - [ ] 论文结论是否落到具体指标/建议，避免空洞口号？
- **人机交互指令**：
  - `/approve`：论文终审通过，执行打包交付。
  - `/refine abstract [修改侧重点]`：调整摘要重点突出内容。
  - `/adjust_length [+页数 / -页数]`：针对特定章节扩充分析或精简图表。

## 3. 标准人机协同审批卡片模板 (Approval Card)

在每个 Checkpoint，AI 必须向人类展示以下标准格式的交互卡片：

```markdown
---
### 📋 [Checkpoint X: 阶段名称] 人机协同审批卡

**1. 当前阶段已完成产出：**
- [产出1简要说明与链接]
- [产出2核心结论/关键数据]

**2. 核心结论与关键指标：**
- 指标A: xxx (相比 Baseline +yy%)
- 关键参数/决策解: zzz

**3. 待决策/审批事项 (Decision Needed)：**
- [ ] 事项1：...
- [ ] 事项2：...

**4. AI 推荐建议与理由：**
- **推荐策略**：...
- **技术理由**：...
- **潜在风险与备选方案**：...

**5. 您可以执行的操作 (Human Action)：**
- 输入 `/approve`：同意当前方案并进入下一阶段。
- 输入 `/revise [修改项]`：调整参数、假设或提出修正意见。
- 输入 `/select [选项]`：选择备选方案。
---
```

## 4. 协同模式切换 (Workflow Modes)

用户可在开始时或随时通过指令设定交互模式：

1. **`Interactive`（强协同模式 - 默认推荐）**：
   - 每个 Checkpoint 严格停下输出审批卡，等待人类明确确认或指导后才执行下一步。
   - 适用于正式竞赛（L2/L3）与重要科研建模。
2. **`Semi-Auto`（半自动模式）**：
   - 自动执行 CP1 到 CP3，在 CP4（验证与数字冻结）和 CP5（论文大纲与定稿）停下请求审批。
   - 适用于时间紧张的模拟赛。
3. **`Auto-Pilot`（全自动模式）**：
   - AI 自行完成全部阶段与 Review，仅在遇到严重矛盾或求解失败时主动中断询问。
   - 适用于快速课程作业（L1）或快速原型验证。

## 5. 模块化单步独立调用指南 (Modular Step-by-Step Invocation)

若用户只需要执行某一个具体步骤，可随时通过快捷指令独立调用，AI 将直接进入对应单步并输出专属成果：

1. **单独调用 `/audit`（审题与数据审计）**：
   - **输入**：题目文本、赛题附件表格。
   - **输出**：生成 `problem_spec.md`（问题规格）、`assumptions.md`（假设清单）、设问递进图与数据缺失/异常审计报告。
2. **单独调用 `/select_model`（方案选型与PoC）**：
   - **输入**：已有子问题描述或 `problem_spec.md`。
   - **输出**：生成 `docs/model_registry.md`（提供 Baseline + 至少2套主模型优劣势对比）及 ≤30行 PoC 代码验证。
3. **单独调用 `/solve`（数学建模与代码求解）**：
   - **输入**：指定的技术方案、数据路径、边界约束。
   - **输出**：输出完整公式推导、Python 求解代码、中间运行解与无弹窗专业图表。
4. **单独调用 `/validate`（模型验证与灵敏度）**：
   - **输入**：已有求解代码与结果。
   - **输出**：输出改装效果对照表、Durbin-Watson 自相关检验、参数敏感度弹性分析（$S = \frac{x}{y}\frac{dy}{dx}$）与 `frozen_numbers.json`。
5. **单独调用 `/write_paper`（撰写LaTeX论文）**：
   - **输入**：各问求解结论、图表路径、关键数字。
   - **输出**：输出严格符合 18~25 页、第1页摘要第2页目录规范的 LaTeX 论文源码及编译后的 PDF。
6. **单独调用 `/review`（论文与代码质量审查）**：
   - **输入**：已写好的论文或代码。
   - **输出**：输出 `review_checklist.md` 审查报告，定位逻辑漏洞、数字不一致或排版问题。
