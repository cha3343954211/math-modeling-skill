# Stage 0: 破题、选题决策与团队分工 (0~6h)

> **阶段定位**：竞赛最关键的前 6 小时。通过多维度量化评估矩阵，选择最切合团队技术栈与数据质量的赛题，制定 72h/96h 攻坚时间线并敲定分工，输出 `topic_decision.md` 与 `competition_brief.md`。

---

## 1. 阶段目标与准入/准出条件

- **输入依赖**：赛题发布（官方题面 A/B/C/D/E/F 文本及附件数据）。
- **准出交付物**：
  1. `competition_brief.md`（赛事规则卡与格式要求）
  2. `topic_decision.md`（选题量化决策表与淘汰理由）
  3. `team_charter.md`（团队三角色分工与攻坚时间表）
- **人机审批点**：`[CP0 审批点]` 队长/全队确认最终选题与时间线。

---

## 2. 团队三角色与 AI 分工

| 角色 | 核心任务 |
|------|---------|
| **AI 助手** | 通读全部赛题，从数据可得性、模型已知性、12h跑通Baseline概率四个维度进行评分，生成候选对比矩阵 |
| **建模手 (队长)** | 结合团队知识背景，评估题目机理推导复杂度与模型创新空间 |
| **编程手** | 快速解压检查所有附件数据集（缺失率、数据格式、字段清晰度、是否需要爬虫） |
| **论文手** | 查阅官方格式规范（语言、页数限制、匿名要求、提交截止时区），准备 LaTeX 模板 |

---

## 3. 选题决策量化评估矩阵模板

在 `topic_decision.md` 中按 1~5 分评估：

| 评估维度 (权重) | 题目 A | 题目 B | 题目 C | 题目 D/E | 评分标准说明 |
|---------------|-------|-------|-------|---------|-------------|
| **数据完整性 (30%)** | | | | | 数据无需大量清洗/缺失少为 5 分；数据缺失严重或需大量补充外源数据为 1~2 分 |
| **机理/算法熟悉度 (25%)** | | | | | 团队有现成掌握的成熟模型库（如规划/ODE/统计）为 5 分；纯陌生领域为 1 分 |
| **12h 内跑通 Baseline (25%)** | | | | | 能够迅速建立可解释基准解为 5 分；前置门槛极高为 1 分 |
| **创新与可视化空间 (20%)** | | | | | 设问递进明确、容易做对比与灵敏度图表为 5 分 |
| **加权总分 (100%)** | **--** | **--** | **--** | **--** | **得分最高且无一票否决项者为推荐选题** |

> **一票否决项**：题目存在无法解决的硬伤（如缺少核心数据且无法合理假设、团队完全缺乏相关软件环境）。

## 4. 赛事规则卡规范 (`competition_brief.md`)

```markdown
# 赛事规则卡
- **赛事名称/年份/组别**：例如 2026 CUMCM 本科组
- **官方题目与下载版本**：C题 (附件1~3 SHA256确认)
- **提交截止时间与时区**：北京时间 YYYY-MM-DD HH:MM:SS
- **论文语言与格式规范**：中文 / 严格遵守正文 18~25 页 / 附录不限页数
- **排版与页码规则**：第1页摘要页、第2页目录页（二级标题），正文从第1页标阿拉伯数字
- **匿名与合规红线**：禁止在正文、页眉、页脚、代码注释、PDF元数据中出现任何个人/指导老师/学校信息
- **支撑材料提交要求**：代码与数据压缩包规范、MD5 校验要求
```
